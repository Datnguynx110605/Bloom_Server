# Catalog Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the catalog service of `doc/low-level-design/08-catalog.md` (API and worker as one app), `Bloom.Catalog.Contracts` (internal proto), the `LaunchStageChangedV1` / `OrderDeliveredV1` payload records, and the gateway route `/api/reviews/**`.

**Architecture:** One ASP.NET Core app `Bloom.Catalog`; `Catalog:Mode` = `api` | `worker` (HLD-ADR-014). API mode hosts four gRPC services, one per LLD §3 component (`CatalogPublic`, `CatalogCustomer`, `CatalogAdmin` transcoded to JSON on the routes below; `CatalogInternal` plain gRPC), plus the shared DLQ admin. Worker mode runs the `Bloom.Shared` outbox relay, consumer host (five consumers), retention purger and a daily pending-image cleanup. PostgreSQL through EF Core (`AddBloom<CatalogDbContext>`), Redis cache-aside with delete-after-commit, S3-compatible object storage through AWSSDK.S3.

**Tech Stack:** .NET 10, ASP.NET Core gRPC + JSON transcoding, EF Core 10 + Npgsql (`tsvector`), StackExchange.Redis, AWSSDK.S3, Markdig, Bloom.Shared, xUnit v3, Testcontainers (PostgreSQL, Redis, RabbitMQ, MinIO), Microsoft.Extensions.TimeProvider.Testing.

**Spec:** `docs/superpowers/specs/2026-11-02-catalog-design.md` (approved; cited "spec §x"). Design source: `doc/low-level-design/08-catalog.md` (cited "§x"). Where the spec is silent, 08-catalog decides; where both are silent, the rulings below decide.

## Owner items (plan approved 2026-11-02)

Items 1–5 approved as recommended with the plan. Item 6 stays a report: no change to `doc/` or `Bloom.Shared` in this branch.

1. **Column `products.updated_at`** (`timestamptz`, set on every product write). Spec §4 sorts `AdminListProducts` "newest-updated first"; the LLD table has no such column.
2. **Column `product_images.created_at`** (`timestamptz`). The daily job deletes `pending` images "older than 24 h" (§6.7); the LLD table has no timestamp.
3. **`GetPricing.name` format.** Order snapshots it on the order line (03-order §4). Recommendation: product name, then the SKU's option values in option-type position order in parentheses: `iPhone 17 Pro (256 GB, Black)`; plain product name when the SKU has no options (plans).
4. **Option filter across products.** Option types belong to one product (§4.1), so two products' "Storage" types have different ids. Recommendation: "same option type" in spec §4 = same option type **name** (case-insensitive). Filter {A's 256 GB, B's 256 GB, A's Black} → groups `storage` {A-256, B-256} AND `color` {A-Black}. Grouping by type id would make every cross-product filter empty.
5. **How a customer gets their review's `version`.** Spec §4 needs `version` to edit, but nothing returns the caller's own review. Recommendation: `ListReviews` adds `my_review` (the caller's own review, any status, with `version`) when the request carries `x-bloom-user-type = customer` (the public route forwards the user when a token is present, LLD 07 `public-optional-user`). Anonymous callers get no `my_review`.
6. **Admin role value still disagrees (carry-over of identity plan item 3, report only).** `Bloom.Shared` `DeadLetterAdminService` checks `x-bloom-role = "Admin"`; identity issues `admin`. No change in this branch (spec §3); Task 13 tests the DLQ mapping with the header the library expects today.

- JSON field names are proto lowerCamel; `int64` fields are JSON strings (proto3 JSON).
- Docker via Colima: never run `colima`; daemon unreachable → stop and report. Never `dotnet run`. Test containers must be gone after the run.
- Every test case C-01 … C-13 has at least one test whose method name starts with its ID: `C01_…`. Test names below are binding; listed assertions are the minimum.

## Review Focus

1. **Concurrent review writes by one customer, and Hide racing an Edit**: two parallel creates → one 200, one `CONCURRENCY_CONFLICT`, `rating_count` 1; an edit with a version read before a hide → `CONCURRENCY_CONFLICT`, aggregates equal a recount of visible reviews. Tests in Task 11.
2. **Visibility leaks**: a plan, draft, archived, launch-`draft` product, an inactive SKU or a `pending` image never appears in `SearchProducts`, `GetProduct` (id or slug), `ListReviews` or a device's `warranty_plans[]`. Tests in Tasks 7, 8, 11.
3. **Redis down**: every public read still answers from Postgres, and admin writes still succeed (invalidation failure is logged, not thrown). Tests in Tasks 3 and 7.
4. **Unsafe Markdown**: `<script>`, inline HTML, `javascript:` / `data:` links and images never reach `description_html`. Test in Task 4.
5. **Out-of-order and repeated launch events**: `announced` after `released` leaves the product `active` and its stage `released`; the same event twice changes nothing more. Test in Task 12.

## Rulings in this plan (builder's calls the spec left open)

- **R1** Tests run the app on `TestServer` (as identity I1). Internal gRPC is called through `GrpcChannel.ForAddress(base, new() { HttpHandler = server.CreateHandler() })`. Tests emulate the gateway with `x-bloom-user-id/type/role`.
- **R2** The app never migrates at startup. Test infra runs `MigrateAsync()` on a fresh database per host. `DesignTimeFactory` serves `dotnet ef` (existing tool manifest).
- **R3** `TryAddSingleton(TimeProvider.System)`; tests register `FakeTimeProvider` first.
- **R4** Config section `Catalog`: `Mode`, `Database`, `Redis`, `RabbitMq`, `Storage:ServiceUrl`, `Storage:AccessKey`, `Storage:SecretKey`, `Storage:Bucket` (default `bloom-product-images`), `Storage:Region` (default `us-east-1`), `Storage:PublicBaseUrl`. Both modes need every key (the worker invalidates the cache and deletes objects). Missing → throw at build naming the key. `appsettings.json` holds non-secret placeholders only (`Mode=api`, `Redis=catalog-redis:6379`, `RabbitMq=amqp://rabbitmq:5672`, `Storage:ServiceUrl=http://minio:9000`, `Storage:PublicBaseUrl=http://minio:9000/bloom-product-images`).
- **R5** `BloomOptions.ServiceName = "catalog"`; telemetry `catalog-api` / `catalog-worker`; meter `Bloom.Catalog`.
- **R6** Both modes register the five consumers (DLQ catalog needs them, as identity I8); only the worker calls `AddWorker()` and adds `ImageCleanupJob`.
- **R7** Roles (identity's values): writes on categories, products, options, SKUs, prices, plans, images, lifecycle, plus `AdminListProducts` / `AdminGetProduct` → `catalog_manager`, `admin`. `HideReview`, `UnhideReview`, `AdminListReviews` → `support`, `admin`. Customer methods → `type = customer`. Refusal → `PERMISSION_DENIED` / `ROLE_NOT_ALLOWED`. Missing `x-bloom-*` on a protected method → `InvalidOperationException` (identity I31).
- **R8** Optimistic locking: every update reads the row, then calls `ConcurrentUpdates.UpdateVersionedAsync(entity, row, request.Version, setters, CatalogErrors.NotFound)` (00-reliability §7.6, counts `optimistic_conflicts_total`). Versioned rows: `category`, `product`, `sku`, `review`. Product-level methods (`UpdateProduct`, `SetOptions`, `SetPlanEligibility`, `PublishProduct`, `ArchiveProduct`, `ReactivateProduct`) take and bump the **product** version and set `updated_at`; SKU methods (`UpdateSku`, `SetSkuPrice`, `SetSkuActive`) take the SKU version. New rows start at version 1.
- **R9** Every write RPC and consumer runs in one explicit transaction. Cache deletes are collected in a scoped `CacheInvalidation` and executed by a `DbTransactionInterceptor` **after commit** (rollback discards them). This gives delete-after-commit for consumers too, whose transaction `ConsumerHost` owns.
- **R10** Cache (§6.3, spec §7): `product:{id}` (protobuf bytes of `ProductView`), `categories` (bytes of `ListCategoriesResponse`), `search:{v}:{hex SHA-256 of the canonical request}` (option ids sorted), `catalog:version`; TTL 10 min. Only visible products are cached. Listing changes (price, active, status, rating, images, options, launch stage, name, category) → `INCR catalog:version`. A plan's price, active, status or eligibility change also deletes `product:{id}` of every eligible device. Any `RedisException`/`RedisTimeoutException`/`RedisConnectionException` on read → miss without `SET`; on invalidation → warning log, write still succeeds. Redis client: `AbortOnConnectFail=false`, `ConnectTimeout=1000`, `AsyncTimeout=1000`.
- **R11** Visibility (spec §7), one source `Visibility`: public product = `kind = 'physical' AND (launch_stage IN ('announced','preorder_open') OR (COALESCE(launch_stage,'released') = 'released' AND status = 'active'))`. Plan shown in `warranty_plans[]` = plan `status = 'active'` and its SKU active. `buyable` (GetPricing) = SKU active AND product `status = 'active'` AND `launch_stage` null or `released`.
- **R12** Derived columns: `ProductDerived.RefreshAsync(Guid[] productIds)` recomputes, in one statement, `min_price_cents` (min over active SKUs, null when none) and `search_vector` = `setweight(to_tsvector('english', name),'A') || setweight(to_tsvector('english', <option values joined by space>),'B') || setweight(to_tsvector('english', <category name>),'B') || setweight(to_tsvector('english', description_md),'C')`. Called in the transaction of every write that changes a price, SKU active, name, options, category (all its products on rename) or description.
- **R13** Audit: `service = catalog`, `actor_id`/`actor_role` = caller, `target_type` ∈ `category | product | sku | image | review`, `target_id` = id `D`. `details`: updates `{before:{…}, after:{…}}` with only the fields the call changed; lifecycle `{before:{status}, after:{status}}`; hide/unhide `{reason}`; everything else `{}`. Actions: `catalog.category-created`, `catalog.category-updated`, `catalog.product-created`, `catalog.product-updated`, `catalog.options-set`, `catalog.plan-eligibility-set`, `catalog.product-published`, `catalog.product-archived`, `catalog.product-reactivated`, `catalog.sku-created`, `catalog.sku-updated`, `catalog.price-changed`, `catalog.sku-activated`, `catalog.sku-deactivated`, `catalog.image-upload-created`, `catalog.image-confirmed`, `catalog.images-reordered`, `catalog.image-deleted`, `catalog.review-hidden`, `catalog.review-unhidden`. Failed calls and no-ops write nothing.
- **R14** Validation (`VALIDATION_FAILED`, `field` = proto field name). Lengths are trimmed Unicode scalars. Category name 1–100; product name 1–200; slug `^[a-z0-9]+(-[a-z0-9]+)*$`, ≤ 100; `description_md` ≤ 20,000; spec group / label / value non-empty; `kind` ∈ `physical | warranty_plan` (immutable after create); plan: `serialized = false`, `coverage_months` 1–120; physical: `coverage_months = 0`; option type name and value 1–50, ≥ 1 value per type, names unique per product and values unique per type (case-insensitive); SKU code `^[A-Z0-9][A-Z0-9-]{0,63}$`; `price_cents > 0`; `alt_text` ≤ 300; review `rating` 1–5, `text` ≤ 2,000 (empty → null); hide `reason` 1–500; page sizes per method. Unknown referenced ids (category, product, SKU, option value of this product, image, review) → `NOT_FOUND`, except plan eligibility pointing at a non-physical product → `VALIDATION_FAILED eligible_product_ids` (spec §4).
- **R15** Options: `SetOptions` sends the whole list; entries with an `id` keep it (rename allowed), entries without get new ids, missing ones are deleted; positions = list order. While the product has any SKU, adding or removing an option **type** or removing a **value** used by a SKU → `VALIDATION_FAILED option_types`. Plans → `VALIDATION_FAILED option_types`.
- **R16** SKUs: `option_key` = the SKU's option value ids sorted (`D` form) joined by `,` (empty for no options). A SKU needs exactly one value of each of the product's option types (`VALIDATION_FAILED option_value_ids`). New SKUs are `active`. `UpdateSku` changes `code` only (the combination is the stock identity). A plan's second SKU → `DUPLICATE_COMBINATION` (same empty key).
- **R17** Lifecycle: `PublishProduct` draft → active, needs ≥ 1 active SKU (`PUBLISH_INCOMPLETE`), sets `published_at` if null; `ArchiveProduct` active → archived; `ReactivateProduct` archived → active (no SKU check). Anything else → `INVALID_LIFECYCLE`. Same rules for plans.
- **R18** Images: extension from type (`jpg`, `png`, `webp`); key `products/{productId}/{uuid}.{ext}`; `position` = max + 1; presigned `PUT` with `Expires = DateTime.UtcNow + 5 min` (credential lifetime, real clock), exact `ContentType`, `Protocol` HTTP when `ServiceUrl` is `http://`. `ConfirmImage` on a `ready` image → success, nothing written. `ReorderImages` must list exactly the product's images (`VALIDATION_FAILED image_ids`). Images have no version (none in §4.1). Public URL = `PublicBaseUrl` + `/` + key. AWS client: `ForcePathStyle = true`, `RequestChecksumCalculation` / `ResponseChecksumValidation` = `WHEN_REQUIRED` (MinIO).
- **R19** Search: `page` ≥ 1 (0 → 1); `page_size` 0 → 24, 1–48, else `VALIDATION_FAILED page_size`; past the end → empty items. `q` with no lexemes (`numnode(websearch_to_tsquery(...)) = 0`) → no text filter (§8). `relevance` without text → `newest`. Ties broken by `id`. Price filters use `min_price_cents` and exclude products with none. Malformed `option_value_ids` → `VALIDATION_FAILED`; ids matching no option value → empty result. Group by option type name (owner item 4).
- **R20** `ListReviews`: page size 20, `page` as R19; newest first by `(created_at, id)` desc; product must be publicly visible, else `NOT_FOUND`. `AdminListReviews` and `AdminListProducts`: `page_size` 0 → 50, 1–100, else `VALIDATION_FAILED`.
- **R21** Review writes lock the review row `FOR UPDATE`; aggregates change on the product row in the same transaction; hide/unhide bump the review `version` (so a stale edit conflicts). Hide of a hidden / unhide of a visible review → success, nothing written. Edit keeps the review's status. Create: product visible → eligibility (`NOT_VERIFIED_BUYER`) → insert (unique violation → `CONCURRENCY_CONFLICT`). Edit and create invalidate `product:{id}` + listings only when the aggregate changed.
- **R22** "First L." (spec §4): trim, split on Unicode whitespace; ≥ 2 words → first word + space + first text element (`StringInfo`) of the last word + `.`; one word → it; none → `Bloom customer`. No case change.
- **R23** Launch events (§6.4): products = union of `products[].productId` and `skus[].productId`; unknown ids skipped. SKU `launch_id` always set. Product update applies when `launch_stage IS NULL OR launch_id <> @launchId OR rank(launch_stage) <= rank(@stage)` (rank draft 0 … released 3); `released` also sets `status = 'active'` and `published_at` if null. Invalidate `product:{id}` of each and listings.
- **R24** `order.delivered.v1`: `INSERT … SELECT` over `productIds` restricted to existing `physical` products; `ON CONFLICT DO UPDATE SET first_delivered_at = LEAST(...)`.
- **R25** Consumers: queue `catalog.<handler>`; handlers `launch-stage-changed`, `order-delivered`, `customer-registered`, `contact-changed` (both → `ReviewerNameConsumer`), `account-deleted`.
- **R26** Metrics (§10): `catalog_read_seconds{endpoint=list_categories|search_products|get_product, cache=hit|miss}` per call; `catalog_cache_hit_ratio{kind=product|categories|search}` observable gauge = hits ÷ (hits + misses) since start (no sample before the first read); `search_seconds` = the Postgres search query (misses); `get_pricing_seconds` per call; `reviews_total{action=create|edit|delete|hide|unhide}`.
- **R27** Test isolation: one database, one MinIO bucket (`c{guid:N}`) and one Redis logical database per test host (Redis started with `--databases 4096`; host N uses `defaultDatabase=N`). Consumer logic is tested by invoking the handler in a scope and transaction like `ConsumerHost` (`Consume.Async`); only `WorkerTests` start worker hosts (one class, so they don't share queues in parallel).
